# Маджонг-дуэли — сервер на Deno Deploy

WebSocket-сервер для соревновательных дуэлей: комнаты по коду,
быстрый матч, одинаковые раскладки по сиду, авторитарное время
и живой реконнект. Клиент (Next.js на Vercel) подключается сюда
по WebSocket.

## Как задеплоить (5 минут, бесплатно)

1. Зайди на **https://dash.deno.com** (регистрация через GitHub).
2. Нажми **New Project**.
3. Выбери **Playground** (самый простой путь — без GitHub-репо):
   - откроется онлайн-редактор;
   - скопируй ВСЁ содержимое файла `main.ts` из этой папки
     и вставь вместо примера;
   - нажми **Save & Deploy**.
   
   Либо классически, через CLI (из этой папки):
   ```bash
   deno install -Arf jsr:@deno/deployctl
   deployctl deploy --project=<имя-проекта> --entrypoint=main.ts --include=.
   ```
4. **Подключи KV-базу** — обязательно, см. следующий раздел
   (без неё сервер либо падал на старте со старой версией кода,
   либо будет работать в урезанном режиме памяти).
5. Через ~20 секунд сервер получит адрес вида
   `https://<имя-проекта>.deno.dev`.
6. Проверь: открой `https://<имя-проекта>.deno.dev/health` —
   должен прийти JSON `{"ok":true, ..., "kv":"deno"}`.
   Если в ответе `"kv":"memory"` — база ещё не привязана.

## Подключи KV-базу (обязательно, 1 минута)

В новом дашборде Deno Deploy KV **не создаётся автоматически**.
Без привязанной базы было так:

```
TypeError: Deno.openKv() failed: no KV Database is attached
   to this app. Attach a KV database to your app in the Deno
   Deploy dashboard, then redeploy.
```

Новая версия кода от этого не падает — сервер стартует в режиме
памяти. Но правильный режим — привязать базу (тогда комнаты,
реванши и счёт серии переживают рестарты изолятов):

1. Открой **https://dash.deno.com** → свой проект
   (например, `mahjong-solitaire`) → в меню слева **Databases**.
2. Нажми синюю кнопку **«Attach Deno KV»** (в блоке Connected
   Databases) — или **«+ Attach»** напротив Deno KV.
3. В появившемся окне создай инстанс: имя любое (например,
   `mahjong-solitaire-databases`), регион ближе к игрокам —
   для России/СНГ **Europe (Frankfurt)**.
4. Deno создаст базу с тремя копиями — `…-local`, `…-preview`,
   `…-production`: прод-копия привяжется к приложению сама
   (таймлайн Production). Статусы должны стать **ready**
   (зелёные).
5. Сделай **Redeploy**: проект → **Deployments** → последний
   деплой → **⋯** → **Redeploy** (в Playground — просто
   **Save & Deploy** ещё раз).
6. Проверь `https://<адрес-приложения>/health` — должно быть
   `"kv":"deno"`.

> Режим памяти (аварийный): без KV сервер работает, комнаты живут,
> пока жив процесс изолята. Ограничения: рестарт изолята = комнаты
> сбрасываются; два игрока на разных изолятах могут не найтись.
> Для игры с другом на постоянной основе — привяжи базу, это
> бесплатно и занимает минуту.
>
> Отладка: принудительно включить режим памяти можно переменной
> окружения `MJ_KV=memory` (Settings → Environment Variables).

## Как сменить адрес подключения в клиенте

Клиент игры (репозиторий на Vercel) тянет адрес из **одной
строки** — файл `src/lib/rooms/serverUrl.ts`:

```ts
export const SERVER_WS_URL =
  process.env.NEXT_PUBLIC_MAHJONG_WS ?? 'wss://<имя-проекта>.deno.dev/ws';
```

Два способа (любой один):

- **Просто правкой файла**: замени `wss://...deno.dev/ws` на свой
  адрес и закоммить — Vercel пересоберёт сам.
- **Через переменную окружения**: в Vercel → твой проект →
  Settings → Environment Variables → добавь
  `NEXT_PUBLIC_MAHJONG_WS` = `wss://<имя-проекта>.deno.dev/ws`
  → Redeploy.

Для локальной разработки: запусти `deno task dev` в этой папке
(сервер на `ws://localhost:8080/ws`) — клиент сам подхватит
локальный адрес, когда открыт с `localhost`.

## Протокол (кратко)

JSON-сообщения по WebSocket `/ws`:

- `hello {uid, name, code?, playerId?}` — подключение и
  **реконнект**: устройство с тем же `uid` молча возвращается
  в свою комнату;
- `create {visibility, level}` → комната + код приглашения;
- `join {code}` → вход по коду/из лобби, сервер выдаёт **seed**
  и `startedAt` (начало отсчёта по часам сервера);
- `event {kind:'match', tile1Id, tile2Id, score, pairsDone}` —
  собрал пару: сервер пересылает сопернику (мгновенный прогресс);
- `finish {reason:'cleared'|'tray'}` — сервер сам считает
  `finalTimeMs = now − startedAt` и рассылает обоим;
- `advance {kind:'rematch'|'next'}` — матч стартует, когда
  согласились оба;
- `leave` — сознательный выход (сопернику — победа «вышел»);
- `match` / `match-leave` — очередь быстрого матча;
- `lobby {on}` — подписка на список ждущих игроков;
- сервер пингует сокеты каждые 5с (фоновые вкладки не «умирают»).

Обрыв связи ≠ проигрыш: место держится 30 секунд, клиент
переподключается и продолжает матч. Состояние комнат живёт
в Deno KV и переживает рестарты сервера (без KV — в памяти
процесса, до ближайшего рестарта изолята).
